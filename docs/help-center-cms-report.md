# Help Center article management

## Delivered
- Admin → Website & Content → Help Center, with Create Article, search/category/status filters, editing, draft/published controls, preview, confirmed deletion and restore.
- Existing category taxonomy, Markdown article format, renderer, public layout and URLs retained. Images reuse the existing media library/upload flow and its alt text.
- Existing articles become editable overrides without changing their slugs or replacing the built-in files. New articles use the same `guide_articles` table.
- Title, summary, category, content, SEO title and description are validated. Blank SEO fields fall back to article defaults. Public canonical URLs remain generated by the existing route.
- Public search, listings, detail pages, neighbours and related articles use the merged published catalogue. Draft and deleted overrides mask their original built-in article; their bodies are not exposed.
- MunchMate's existing refresh indexes the same published catalogue. Removed/unpublished help entries are excluded from retrieval immediately; refresh removes stale automatic index entries. Edited answers are refreshed using the existing Admin → AI Support Settings knowledge refresh.
- User Guide & Alerts excludes Help Center rows and cannot edit/delete those overrides through its existing endpoints.

## Owner setup required
Apply `supabase/manual/help-center-cms.sql` to the live database after review. It only adds three columns and a slug-only public function, preserving existing rows, grants and admin RLS. No SQL was executed here. Existing public articles continue to render before setup; the new Admin page reports the setup requirement.

Deletion is reversible: it sets `published=false` and `deleted_at`, never physically deletes article data or images. Restoring and saving clears the marker.
