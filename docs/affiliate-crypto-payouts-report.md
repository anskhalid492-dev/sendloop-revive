# Affiliate and agency crypto payout update — not activated or published

## Implemented
- Existing affiliate portal and existing Admin affiliate console updated, not duplicated. Affiliate wallet tab supports USDC/Ethereum and USDT/Tron (TRC20), address checksums, explicit network/address confirmation and saved wallet updates.
- Crypto-only requests, fixed $100 USD minimum, available balance and one pending request per affiliate. Payout destinations are snapshotted so wallet edits cannot redirect pending requests. Manual processing deadline is 60 days after request, not a new commission hold or an automatic payment scheduler.
- Payout history includes actual paid amount, status, date, transaction hash and private proof links. Pending/approved requests reserve funds; rejection releases the reservation. Partial payment closes the request and releases its unpaid remainder.
- Admin payout management includes live/test earnings totals, commission counts, pending/approved/paid amounts, request/completed counts and outstanding net payout liability. Existing latest-200 payout inventory retained.
- Approve, Processing, Paid and Reject actions use locked transactions; Paid requires prior approval, actual amount and transaction hash. A unique normalized hash per network prevents reuse; duplicate retries cannot settle twice. No crypto transfer is initiated by the application.
- Positive/negative manual balance adjustments are append-only, require a reason and record before/after balances, actor, timestamp, environment and idempotency key. Full adjustment history is paged. Adjustments never overwrite commissions or attribution.
- Private payment proofs use existing R2 integration in a separate `affiliate-proofs/<payout>/<uuid>` namespace; only owner/admin access is signed, for five minutes. Metadata and audit are registered transactionally. PNG/JPEG/WebP/PDF, actual magic-byte validation, 5 MB maximum, authenticated administrator upload and rate limits. Support users are not authorized.
- Public `/referral` and `/referral/agencies` now explain supported crypto networks, $100 minimum, manual processing within 60 days and tracking. Agency page has a distinct left-aligned introduction and client-focused section. Existing configured monthly/annual/lifetime rates remain unchanged.

## Verification and limitations
- Existing Stripe handlers/billing/commission percentage rules were not modified; existing regression tests remain in place.
- Database tests execute the proposed SQL only in an in-memory PGlite instance, with explicitly named crypto-test fixtures and no production network/data access.
- Public desktop/mobile page checks passed at 1280×1800 and 390×844, including crypto section rendering, no overflow and no page errors.
- Authenticated full-portal end-to-end checks are unavailable with this externally managed backend. UI/backend save, attachment readback and actual R2 upload remain unverified; local permission/ledger regressions do not substitute for these checks.
- Payout inventory remains capped at 200 admin / 50 affiliate requests; adjustment audit is fully paged. Liability is net spendable approved earnings (including reserved requests), not pending/unapproved commissions. Wallet validation cannot establish that the affiliate controls the destination or that it can receive tokens.
- Existing commission hold settings still apply; the 60-day manual request deadline is separate. Payout token quantity/exchange fees are team-managed; recorded paid amounts remain USD. No automatic payments, activation, production data modifications, migrations or publication occurred.
