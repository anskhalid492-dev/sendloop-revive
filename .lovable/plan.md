# Rebuild the Warmup product page

## Goal
Replace the existing `/product/warmup` page in place with a premium, light SaaS product page that explains the real MunchReach warmup system. Keep the shared MunchReach header, footer, typography, colors, buttons, and mobile behavior. No product, sending, scheduling, mailbox, or database behavior will change.

## Page structure
1. **Hero** — Use the supplied eyebrow, headline, supporting copy, two CTAs, and the statement “Warmup runs separately from your campaign sending.” Place a restrained mailbox-health preview beside the copy on desktop and below it on mobile.
2. **Why warmup matters** — Three concise cards for gradual ramp, reputation protection, and consistent sending.
3. **How it works** — A strong four-step Connect → Start → Increase → Monitor flow; horizontal on desktop and vertical on mobile.
4. **Real product view** — A large, clearly illustrative MunchReach warmup/email-accounts interface based on the current product, with small callouts for mailbox status, health, limits, activity, and issues.
5. **Warmup settings** — Reproduce the real Conservative, Balanced, and Aggressive presets plus supported start volume, maximum volume, ramp, schedule, bounce/health thresholds, and auto-pause controls. Explain that presets remain bounded by mailbox health and limits.
6. **Warmup vs campaigns** — A prominent two-column comparison explaining that warmup activity and reporting remain separate from prospect campaigns and campaign analytics.
7. **Mailbox health** — Show supported mailbox states and health language without fabricated results. Explain that health is based on recent sends, bounces, complaints, temporary failures, authentication, and other recorded signals, and never guarantees inbox placement.
8. **Safety controls** — Four compact cards for bounce protection, complaint protection, automatic pause, and clear recovery reasons, without publishing backend thresholds.
9. **Warmup activity** — A large illustrative activity/history view using the real planned volume, sent, replies, bounces, failures, health, and ramp-action concepts. State visually that warmup messages do not enter normal inbox or campaign reporting.
10. **Manage every mailbox** — A full-width responsive table based on real Email Accounts concepts: mailbox/domain, status, warmup, health, limits, campaign assignment, and recent activity.
11. **Before and after** — Use the supplied non-guaranteed comparison.
12. **Who it is for** — Agencies, sales teams, founders, and recruiters/B2B teams.
13. **Why MunchReach Warmup** — Six compact capability cards using only existing functionality.
14. **Customer reviews** — Keep the existing real-review feed, which already removes itself when no real reviews exist. No sample testimonials or logos.
15. **FAQ** — Use the ten requested questions in the existing accordion, with short answers aligned to actual behavior.
16. **Final CTA** — Use the supplied heading, supporting copy, “Start Sending Free,” and “Explore MunchReach.”

## Visual direction
- Use a spacious light canvas, existing blue-led palette, restrained violet accents, clean borders, subtle shadows, and Lucide line icons.
- Make product interfaces the visual focus; avoid decorative gradients, oversized empty areas, nested cards, and fabricated customer-looking screenshots.
- Label code-rendered product visuals as illustrative where sample values are necessary.
- Add subtle reveal/flow motion using existing page animation patterns and respect reduced-motion preferences.
- Keep every table usable on mobile through condensed cards or contained horizontal scrolling, with no page-level overflow.

## Product accuracy decisions
- Replace the old fixed “Stage 1 of 6” marketing examples with the real Ramp Up, Stable, Hold, Recovery, and Pause model and day/history language.
- Use actual customer controls: enable, pause, resume, settings, health, current volume, issues, and history.
- Use actual settings: presets, start/max volume, daily increase/ramp period, sending days/window, bounce/health protection, and auto-pause.
- Describe authentication as verified where supported and “Manual verification required” otherwise.
- Explain capacity truthfully: human replies and campaigns take priority; warmup uses remaining mailbox capacity and stays separate from campaign metrics.
